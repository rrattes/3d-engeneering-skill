## G-code side effect

The Orca `--slice` operation writes a transient `plate_1.gcode` even when requesting a sliced 3MF. The adapter extracts metrics and immediately deletes that file; the report marks the action. No standalone G-code is retained/delivered, and no upload, printer protocol, network, or print start occurs. A regression assertion verifies the transient G-code is absent after slicing.

## Limits and next steps

- `PASS` indicates the real CLI completed, exact presets matched, and the sliced 3MF passed package integrity/content checks. `printer_compatibility` is preset-chain-only. It does not prove the Elegoo application/device will accept this 3MF.
- Physical print validation remains `NOT_EVALUATED`; no part was printed or dimensionally measured.
- Six orthogonal orientation candidates are heuristics and only currently supported for STL input. Comparison optimizes parseable slicer time, not mechanical strength or reliability.
- Envelope enforcement uses an axis-aligned bounding box and configurable uniform margin. It does not account for all clips, bed exclusions, purge towers, or machine-specific keep-out zones.
- Support is read from Orca metadata when available. No structural optimization, multicolor/Combo control, automatic profile updates, printer communication, or standalone G-code delivery is implemented.
- The image is about 1.47 GB due to Orca's actual runtime and profile bundle.

Next V1.3.x steps: test vendor-app import compatibility on the exact receiving application version, compare with a small physical calibration print, add reviewed presets one nozzle/material at a time, and keep any new slicer metrics explicitly `NOT_EVALUATED` until verified against real output metadata.
